# Solomantalgo agent entry point

**Shared workflow location:** `C:\Solomon\Projects\AgentWorkflow`. The GitHub repository is `https://github.com/Solomantalgo/Agentworkflow.git`. Agents may commit and push changes to this workflow repository when they update these instructions. Check the diff and repository state first. If no `origin` remote is configured, push to the explicit repository URL. For a client repository, use that client's own remote and scope.

For any Solomantalgo client website or web system task, read these files before proposing or building anything:

1. `BUSINESS_REFERENCE.md` — business positioning and operating context.
2. `PACKAGES.md` — current website packages, add-ons, and maintenance terms. This file can change; always read its current contents.
3. `SITE_WORKFLOW.md` — required planning, visual exploration, handoff, implementation, and review process.

Each client project gets its **own planning agent/session**, assigned to one named client. The **planning agent is the owner's only point of contact** from discovery through final review. It owns requirements, recommendations, scope, references, assets, design directions, the implementation plan, builder coordination, and final review. It posts the exact builder prompt **in chat**, then dispatches and supervises the builder itself when delegation is available. The owner must not be told to contact, brief, answer questions from, or manage the builder. Builder questions go to the planner; the planner answers from the record or asks the owner a concise, structured question when essential. If delegation is unavailable, the planner continues the work in its own session and explains the limitation. The shared files provide Solomantalgo standards; they do not give the agent an ongoing role across all clients.

Start a new client session with `templates/CLIENT_PLANNER_PROMPT.md`. After discovery has gathered the essential requirements and references, create that client's `PROJECT_PLAN.md` from `templates/PROJECT_PLAN.md`; refine it as design decisions are made. Keep client-specific information, decisions, references, and assets in that client's project files, not in shared business files. Before handoff, inspect the existing site if any, locate and verify every required reference and asset, create suitable missing assets, and make useful scope/design recommendations. Do not ask the builder to collect owner decisions or find an asset known only to the planner. Do not treat a package price alone as a complete client brief. Do not begin full site implementation before the owner selects a direction and approves the implementation brief for a new design; focused updates follow the smaller change-plan path in `SITE_WORKFLOW.md`.

At the start of a session, after a context reset, and before each handoff, reread this file and the client plan's decision log. Preserve confirmed answers there and never ask the owner to repeat information already available in chat or project files. Record unknowns explicitly; do not invent client facts, content, services, prices, or completed functionality. Do not carry another client's design, facts, or approvals into this project.
